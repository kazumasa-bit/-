# 提案：社内課題を「AIと一緒に、一歩ずつ、直しながら」完成させるフォーマット

## 0. 最初に：ご相談内容の理解

いただいた話を、こう理解しました。認識がズレていたらここだけ直してください。

- **課題の例**：店長候補（社員）が足りない
- **やりたいこと**：その課題を解くために、AIと一緒に「タスクの流れ」を設計したい
  例：求人募集 → 応募 → 面接 → 選考基準 → 採用 → 入社 → 立ち上がり → 定着 → 育成 → 店長昇格
- **AIにしてほしいこと**：流れの中の**一つ一つのステップに対して「選択肢」を出す**こと
- **決めるのは人**：選ぶのは、それを実際に使ううちのスタッフ
- **一番の悩み**：作ったあと必ず修正が出る（エラーが出る／感覚が違う／方向が違う）。
  その修正が**しやすい設計フォーマット**がほしい。そして最後まで作り切れる形にしたい。

つまり欲しいのは「採用の答え」ではなく、**課題を入れたら完成まで運べる“型”**です。
以下、その型の設計です。

---

## 1. なぜ普通のやり方だと途中で崩れるのか

AIに「採用の仕組みを作って」と頼むと、長い文章が一枚返ってきます。これが崩れる原因です。

| 起きること | 理由 |
|---|---|
| 直したい所だけ直せない | 全部が一枚に繋がっていて、どこを触ればいいか分からない |
| 直したら別の所が壊れる | どの決定がどこに影響するかが書かれていない |
| 「なんか違う」が毎回再発する | ズレた理由がどこにも保存されず、次回も同じズレが出る |
| いつ終わりか分からない | 「完成」の条件がない |
| スタッフが使えない | AIが勝手に決めていて、現場の判断が入っていない |

**結論：修正しやすさは、文章の上手さではなく「構造」で決まります。**

この提案の中心は一つだけです。

> ### 成果物を「カード」という小さな単位に割り、AIには一度に1枚だけ書かせる。
> ### 修正は「カード1枚の差し替え」で済むようにする。

---

## 2. 全体構造：5つの階層とアドレス

すべての中身に**住所（ID）**を振ります。住所があると「そこを直して」と一言で指定できます。
これが“修正しやすさ”の正体です。

```
L0  課題        Issue      なぜやるのか           例) 店長候補が足りない
 └ L1  北極星    Goal   G1  どうなったら勝ちか      例) 12ヶ月で店長候補を3名内部輩出
    └ L2  局面   Stage  ST3 大きな流れの一区切り    例) ST3 選考
       └ L3  ステップ Step  S3-2 現場の作業単位     例) S3-2 面接の評価基準をつくる
          └ L4  選択肢 Option O3-2-B AIが出す案     例) B案 4象限スコア評価
             └ L5  決定 Decision D-0007 人が選んだ記録
                  実行 Run      RUN-0007 やってみた結果
                  修正 Revision R-0012 直した記録
```

会話がこうなります。

- ❌「面接のとこ、なんか違うから直して」
- ⭕「**S3-2 が R2（感覚ズレ）**。うちの現場だと圧迫に見える。うちらしさカードに追記して書き直して」

AIは迷いません。**どのファイルを、なぜ、どう直すかが一意に決まる**からです。

---

## 3. 使うカードは6種類だけ

覚えることを増やさないため、カードは6種類に絞ります。

| # | カード | 役割 | 誰が書くか |
|---|---|---|---|
| 1 | **北極星カード** | 課題と、勝ち条件（KPI）と、期限 | 人（AIが下書き） |
| 2 | **うちらしさカード** | 自社の前提・価値観・過去の失敗・禁止事項 | 人（ズレるたび追記） |
| 3 | **ステップカード** | 1作業単位。入力/出力/完成条件 | AIが下書き → 人が承認 |
| 4 | **選択肢カード** | そのステップのやり方 3案＋推奨 | **AIが必ず出す** |
| 5 | **決定ログ** | 誰がいつどの案を選び、なぜ選んだか | 人（スタッフ） |
| 6 | **修正ログ** | 何がズレて、どう直したか、影響先はどこか | 人＋AI |

テンプレートは `format/` に全部入れてあります。

---

## 4. 回し方：5フェーズのループ

```
   ┌──────────────────────────────────────────────┐
   │                                              │
   ▼                                              │
① DESIGN  AIがステップに分解し、各ステップに選択肢を3案出す
   │
   ▼
② DECIDE  スタッフが選ぶ。理由を1行で残す（← ここは絶対に人）
   │
   ▼
③ DO      選んだ案を実行する（求人を出す、面接をやる、など）
   │
   ▼
④ DETECT  ズレを検知する。ズレを4つの型のどれかに分類する
   │
   ▼
⑤ DIFF    型に応じて、直す場所を決めて直す ───────────────┘
```

**AIは①と⑤を担当。②はスタッフ。③は現場。④は両方。**
この役割分担を崩さないことが、この仕組みの生命線です。

---

## 5. 【最重要】修正を4つの型に限定する

「エラーが出る」「感覚が違う」「方向が違う」——おっしゃったこの3つを、型として定義しました。
**修正が型に収まると、直す場所と影響範囲が自動的に決まります。**

| 型 | 症状 | 本当の原因 | 直す場所 | 影響範囲 |
|---|---|---|---|---|
| **R1 実務エラー** | 手順が物理的に回らない。抜けがある | ステップの作り込み不足 | そのステップカードだけ | 局所（そのステップのみ） |
| **R2 感覚ズレ** | 間違ってはいないが「うちっぽくない」 | **うちらしさカードの記述漏れ** | うちらしさカードに追記 → 関係カードを再生成 | 中〜広（今後の全出力） |
| **R3 方向ズレ** | そもそも選んだ案が違った | 決定時の判断軸が足りなかった | 決定を差し戻し → 選択肢カードから選び直し | そのステップ＋下流 |
| **R4 前提変化** | 目的やKPI自体が変わった | 外部環境／経営判断の変化 | 北極星カードを改訂 → 全体を棚卸し | 全体 |

### ここが肝：R2（感覚ズレ）の扱い方

「なんか違う」は、AIのミスではなく**うちの暗黙知が書かれていないだけ**です。
だから R2 が出たら、**必ず「うちらしさカード」に1行足してから**直します。

```
1回目：「その求人票、うちっぽくない」→ うちらしさカードに追記
        「“アットホーム”は使わない。過去に応募が地雷化した」
2回目以降：AIは最初からその表現を避ける
```

**ズレるたびにカードが太り、AIの精度が上がる。**
つまり修正が損失ではなく**資産の蓄積**になります。これがこのフォーマットの一番の価値です。

## 6. AIに守らせるルール（AI憲法）

`format/30-AI指示書.md` にそのまま貼れる形で置いてあります。要点：

1. **AIは決めない。** 必ず3案（少なくとも2案）＋推奨1案＋その理由を出す。
2. **選択肢は必ず同じ5軸で採点する**（比較できないと選べないため）
   `コスト / スピード / 現場の手間 / 再現性（仕組み化しやすさ） / リスク`
3. **1回の出力は1カードだけ。** 長文で全部返さない。
4. **前提が足りないときは推測しない。** 「不足情報」として質問に落とす。
5. **出力の前に必ず「うちらしさカード」を読む。**
6. **各ステップには必ず「完成条件（DoD）」を1文で書く。**
7. **変更したら、影響を受けるカードIDを必ず列挙する。**

---

## 7. 「完成」の定義

終わりを決めないと永遠に直し続けます。2段階で定義します。

- **ステップの完成**：DoD（完成条件）を満たした実物がある
  例）S3-2 の DoD =「面接官2名が同じ候補者を採点して、評価が±1点に収まる」
- **仕組み全体の完成**：全ステップが DoD を満たし、かつ **担当者を変えて2回連続で回った**

2回連続で回る＝再現性がある＝仕組みになった、という判定です。

---

## 8. 導入ロードマップ

| 段階 | やること | 期間の目安 | 道具 |
|---|---|---|---|
| **Phase 0** | 北極星カード＋うちらしさカードを埋める | 半日 | このリポジトリのテンプレ |
| **Phase 1** | 採用テーマ1本を、選択肢出し→決定→実行まで完走 | 1ヶ月 | Markdown＋Claude |
| **Phase 2** | 決定ログ・修正ログが溜まる。カードをNotion/スプレッドシートへ | 2〜3ヶ月 | Notion or スプレッドシート |
| **Phase 3** | 定型ステップを自動化（求人票生成／応募者スクリーニング／面接サマリ） | 3〜6ヶ月 | Claude＋Make等 |
| **Phase 4** | 他テーマへ横展開（売上・原価・教育）。カード資産が効く | 6ヶ月〜 | 同上 |

**Phase 0 と 1 は今日から紙とテキストだけで始められます。**
システムを作るのは、手で2周回して型が固まってからで十分です（先に作ると必ず作り直しになります）。

## 9. サンプル：店長候補が足りない → 店長輩出まで

`examples/saiyo-tencho/` に実物を置きました。局面分解はこうです。

```
G1  12ヶ月で店長候補を3名、内部から輩出する

ST1 要件定義   どんな人が、何人、いつまでに必要か
ST2 母集団形成 求人を出して、応募を集める
ST3 選考       基準をつくり、面接し、見極める
ST4 内定〜入社 承諾率を上げ、辞退を防ぐ
ST5 立ち上がり 入社90日で一人前にする
ST6 定着       辞めさせない
ST7 育成・昇格 店長要件を定義し、昇格させる
```

このうち **S2-1「求人媒体を決める」** を、選択肢カードまで完全記述したサンプルにしてあります。
「AIが出す選択肢とはこのレベルのもの」という基準にしてください。

---

## 10. まず決めていただきたいこと（3つだけ）

このあと進めるために、判断が要るのはここだけです。

1. **最初のテーマ**：採用（店長候補）で合っていますか？別の課題が先ならそちらに差し替えます。
2. **決定者は誰か**：選択肢を選ぶスタッフは誰ですか？（1人 or 会議体か）
3. **置き場所**：当面このリポジトリのMarkdownで回すか、Notion/スプレッドシートに移すか。

決まり次第、`examples/` を実データで埋めて1周目を回します。
