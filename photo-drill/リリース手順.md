# リリース手順

## 0. 先に決めること（チェックリスト）
- [ ] 商品名（仮：おいしい写真ドリル／こども写真ドリル）
- [ ] 価格（仮：各2,980円。2つセット割も検討）
- [ ] 無料の範囲（今は最初の2章）
- [ ] 販売者名の表記（個人名 or 屋号）
- [ ] 問い合わせ用メールアドレス

## 1. 中身を仕上げる
1. 試用版を自分で全部やる（気になる文章はメモ → `src/content/<版>.js` を直す）
2. `撮影リスト.md` を見て見本写真を撮り、`photos/<版>/` に入れる
3. モニター3〜5人に無料で使ってもらい、わかりにくい所を直す

## 2. 決済ページを作る（おすすめ：Stripe Payment Links）
1. Stripeに登録（本人確認・口座登録）
2. 商品を作成 →「支払いリンク」を作る
3. 支払い完了後の画面で「確認ページをカスタマイズ」を選び、次の文を表示する
   > ご購入ありがとうございます。購入コード：**CAFE-XXXX-XXXX**
   > アプリの「購入コードを入力」に入れると、全ミッションが開きます。
   > アプリはこちら：https://（公開したURL）
4. 支払いリンクのURLを `src/content/<版>.js` の `url: ""` に入れる

※ STORES・BASE・note でも同じ流れで販売できます（デジタルコンテンツ販売、購入者に表示するメッセージにコードを書く）。

### 購入コードについて
- コードは `codes.json` にあります（Gitには保存されない設定です。**必ず自分でも控えておく**）
- コードを変えたいとき：`codes.json` の中身を書き換えて `python3 build.py` → 公開し直す
  （古いコードを残しておけば、前に買った人もそのまま使えます：`"cafe": ["新しいコード", "古いコード"]`）
- v1は簡易方式なので、コードが出回る可能性はあります。売れ始めたら購入者ごとのコード（ライセンスキー）方式に切り替えましょう

## 3. ビルドする
```
cd photo-drill
python3 build.py
```
`dist/cafe/` と `dist/mama/` が公開用のフォルダです。

## 4. 公開する（無料・どれか1つ）
| サービス | やり方 |
|---------|-------|
| Netlify | netlify.com に登録 →「Deploy manually」に `dist` フォルダをドラッグ＆ドロップ |
| Cloudflare Pages | GitHubと連携して `photo-drill/dist` を公開フォルダに指定 |
| GitHub Pages | リポジトリ設定 → Pages（リポジトリを公開にする必要あり） |

公開URLの例：`https://xxxx.netlify.app/cafe/`、`https://xxxx.netlify.app/mama/`
独自ドメイン（例：photo-drill.jp）は年1,000〜3,000円ほど。

## 5. 販売ページ・法律まわり
- 販売ページ（構成は `../iphone-photo-course/06_集客・販売戦略.md` の6-6）
- **特定商取引法に基づく表記**（販売者名・住所・電話・メール・価格・支払方法・引き渡し時期・返品条件）
  - 個人で住所を出したくない場合は「請求があれば遅滞なく開示します」とする方法あり
- **割引の表示は本当のものだけ**（実際に売ったことのない「通常価格」の取り消し線、期限のないカウントダウンはNG）
- 利用規約・プライバシーポリシー（アプリは端末に記録を保存するだけで、個人情報は集めていないことを明記）

## 6. 新しい版（ターゲット）を増やすとき
1. `src/content/cafe.js` をコピーして `src/content/<新しいid>.js` を作る
2. `id`・名前・色・ミッションを書き換える（`id` は英小文字）
3. `python3 build.py` → `dist/<新しいid>/` ができる

ほかの候補：飲食店・お店オーナー版（メニュー写真・商品写真）、シニア版、ペット版、旅行版、ハンドメイド・メルカリ版

## 7. v2でやりたいこと
- 購入者ごとのコード（ライセンスキー）・サーバーでの確認
- アカウントでの記録保存（機種変更しても続きから）
- 修了証の画像を作ってSNSでシェア（口コミ集客）
- 見本の短い動画
