# 自然農業シミュレーター — マイ畑のデータが消えた件

## 調べたこと

アプリ本体（Google ドライブ `自然農業シミュレーター/_deploy/`）のコードを読んだ結果:

- マイ畑の記録は、端末のブラウザの `localStorage` に **`shizen-mine`** というキーで保存される（`app.js:99`）。
- `shizen-mine` に書き込むのは、追加・工程の更新・チェック・削除の**操作をしたときだけ**（`app.js:949,1087,1103,1119,1135,1162`）。
  起動時に空で上書きするような処理はない。
- 作物データ（`data/grow.js` / `data/crops.js`）から作物が消えても、記録は消えずに出る作りになっている
  （`app.js:767` 「詳細データ（GROW）が無い作物でも、登録した記録は必ず表示する」）。
- `sw.js` はキャッシュだけを扱い、`update.html` も Service Worker とキャッシュを消すだけで、
  どちらも `localStorage` には触っていない。

→ **アプリの編集そのものがデータを消す作りにはなっていない。**

## では、なぜ見えなくなるか

`localStorage` は「アドレス（オリジン）ごと・ブラウザごと」に分かれて保存される。中身が消えたのではなく、
**別の保存先を見ている**可能性が高い。順に疑うべきもの:

1. **アドレスが変わった（原因の本命）** — Drive のメモ `reference_shizen_nogyo_app.md` に、
   2026-09-01 に Netlify から Cloudflare Pages へ引っ越したと記録がある
   （Netlify 無料枠が credit usage exceeded になり新規デプロイ不可になったため）。

   | | アドレス |
   | --- | --- |
   | 旧（結の畑） | `https://yui-no-hatake.netlify.app` |
   | 旧（改名後・中身が古いまま残存） | `https://shizen-nogyo.netlify.app` |
   | 現在 | `https://shizen-nogyo.pages.dev` |

   ドメインが変われば `localStorage` は引き継がれない。引っ越し前に登録した野菜は旧アドレス側に残っている。
   Netlify は「新規デプロイ不可」であって既存サイトは配信され続けるため、旧アドレスはまだ開ける見込み
   （このコンテナからは外部接続が塞がれており未検証）。
2. **デプロイごとの別アドレス** — Cloudflare Pages は `<ハッシュ>.shizen-nogyo.pages.dev` も発行する。
   更新後にそのリンクを開くと本番とは別の保存先になり、まっさらに見える。
3. **ホーム画面のアイコンと Safari で保存先が分かれている** — iOS では別々になることがある。
   アイコンを消して入れ直すと、そのぶんの保存が失われることもある。
4. **iOS の自動削除** — Safari は、7日間開かなかったサイトの保存データを自動で消す（ホーム画面に入れたアプリは対象外）。
5. 履歴・サイトデータの消去、プライベートブラウズ。

## 入れたもの: `rescue.html`

`_deploy/` に置いて `https://shizen-nogyo.pages.dev/rescue.html` で開くと、その端末・そのアドレスについて:

- いま見ているアドレスを表示（本番か、デプロイごとの別アドレスかを見分けられる）
- マイ畑の記録が何件残っているか
- 保存されているものの一覧（いまの名前 / 古い名前の区別つき）
- 古い名前（`yui-mine` など）が残っていればいまの名前へ戻す
- 全部を文字として書き出す（コピーしてメモやLINEに残す）／貼りつけて復元する

旧アドレス（Netlify）には新規デプロイができないので、`rescue.html` を置けない。そちらからは
パソコンの Chrome の開発者ツール（F12 → Console）で1行流して書き出す。その1行は `rescue.html` の中に
コピーできる形で載せてあり、出てきた文字をこのページの「読み込み」に貼れば戻る。
読み込み後は `yui-*` を現行キーへ移す処理が自動で走る（アプリ側の移行処理は `shizen-mine` が
空配列だと動かないため、こちらで補っている）。

### 置き方

`rescue.html` を `自然農業シミュレーター/_deploy/` に入れて、いつもどおりデプロイするだけ。
既存のファイルは変更していないので、アプリの動きには影響しない。

`sw.js` の `ASSETS` には追加していない（オフラインで開く必要のないページのため）。
オフラインでも開けるようにするなら `ASSETS` に `'rescue.html'` を足し、`CACHE` のバージョン番号を上げる。

# マイ畑の使いやすさと、朝のLINEの整理

「予定も登録しないとLINEに出ない → でも全部登録すると一覧が長すぎて、いざまく時に探せない」
という問題への対応。3つに分けて入れた。

## ① 画面の並べ替え（`app.js`・**これだけで効く。単独で入れてよい**）

マイ畑の一覧を3段に分けた。

| | 中身 | 表示 |
| --- | --- | --- |
| 🔔 いま出番 | 予定のうち、今月／来月がまき時のもの | 最上部。ボタンを押すだけで今日の日付が入る |
| 育てているもの | 予定以外 | 着手日の新しい順。解説・チェックリストつき |
| 📌 これから育てる | 残りの予定 | 折りたたみ。まき時が近い順 |

予定カードは解説を出さない（数が増えても短い）。作物名・科・別名での絞り込み欄も足した。

## ② 各画面の説明（`app.js`・単独で入れてよい）

「何の画面で、どこと繋がるか」を画面のあたまに常時表示。
今月やることの末尾に「この5つの画面は、どう繋がっているか」を折りたたみで置いた。

## ③ 朝のLINEの重複整理（アプリ＋畑Bot・**両方そろって初めて動く**）

いまの朝の便は、GASに直書きした年間期限26本だけを見ている。マイ畑は端末の中にあるので
畑Botからは読めない。そこでマイ畑を畑Botに預け、1作物1行に整理する。

**ルール（マイ畑が勝つ）**

| マイ畑の状態 | 朝のLINE |
| --- | --- |
| 登録なし | 期限表のまま（今までどおり。網羅性は落とさない） |
| 予定で登録あり | 期限の行に「📌 マイ畑に予定あり」を付けて1行だけ |
| もう着手した | 期限の行は**出さない**。末尾に「◯◯ は着手済みなので省きました」 |
| 期限表に無く、予定のまき時 | 「── マイ畑から ──」として足す |
| 育成中で、今月が穫れる月 | 「そろそろ穫れます」を足す |

去年の記録を「済んだ」と取り違えないよう、着手済みとみなすのは
**その期限の60日前より後に始めたもの**だけ。

### 入れ方

1. **`app.js`** を `_deploy/` に置く（①②だけならここまでで完了）
2. **`sync.js`** を `_deploy/data/sync.js` として置き、`url` と `token` を入れる
   - `url` … secrets.env の `HATAKE_BOT_EXEC_URL`（末尾 `/exec`）
   - `token` … 長いランダム文字列。**公開サイトのJSに載る**ので他のトークンと必ず別にする
3. **`index.html`** の `<script src="data/alias.js"></script>` の次の行に
   `<script src="data/sync.js"></script>` を足す（`app.js` より前に読ませる）
4. **`sw.js`** の `ASSETS` に `'data/sync.js'` を足し、`CACHE` の版番号を上げる
5. **`hatake_bot_mine.js`** の中身を `hatake_bot/main.js` の末尾に足し、
   ファイル内のコメントどおり `doPost` の先頭3行と `htkSection_` を差し替えて `clasp push`
   - `HTK_MINE_TOKEN` は手順2の `token` と同じ値にする
6. デプロイ
   `npx wrangler pages deploy "<_deployのパス>" --project-name shizen-nogyo --branch main --commit-dirty=true`

`sync.js` が空のまま、あるいは置かれていなくても、アプリは今までどおり端末の中だけで動く
（マイ畑の画面に「いまは畑Botと繋がっていません」と出る）。

### 気をつける点

- **トークンは公開される。** 漏れてもできるのは「マイ畑の控えの書き換え」まで。
  読み取り／管理用トークンとは必ず分ける。
- **どの記録があるかはアプリが決める**（消したら控えからも消える）。
  工程の進み具合だけ、更新が新しいほうを採る（LINEで進めた分がアプリに戻る）。
- **年間期限が2か所にある**（`data/calendar.js` と GAS の `HTK_DEADLINES`）。
  GAS のコメントにも「変更時は両方直す」とある。いずれ GAS 側を消して
  アプリ側だけを正本にするのが本筋。

### 確かめたこと（Chromium／Node）

- 3段の分かれ方・折りたたみ・絞り込み・ワンタップで今日の日付が入ること
- 説明が3タブとも出ること、折りたたみが開くこと
- 起動時に預け、畑Bot側で進んだ工程が戻ってカードが移ること
- 記録を変えると1.5秒後にまとめて送り直すこと
- `sync.js` が空なら**外に一切通信しない**こと（タブを5回行き来して0件）
- 重複整理: 着手済み→省く／予定→印をつける／去年の記録→省かない／
  期限表に無い予定のまき時と収穫期→足す
